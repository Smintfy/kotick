`<Shiru />` is a development overlay for React apps that use state machines. It lists each machine that runs on the page and all of its states, also the states the UI never went to. Click a state to show it in the real app, with real layout and data. You do not have to click through the flow, slow down the network, or force an API error to get there. shiru supports `useReducer` machines through `shiru/reducer`, and XState v5 machines through `shiru/xstate`.

## How it works

<CheckoutDemo />

During a preview, your components get the selected state in place of the real one, and the real machine continues to run. With `shiru/reducer`, `useMachineReducer` returns it. With `shiru/xstate`, they read the state from a proxy of the actor. For the adapters, the registry and the overlay, see [How shiru works](/docs/concepts#how-shiru-works).

## Why shiru

| Benefit | What it means |
|---|---|
| [In context](/docs/concepts#previews) | Previews render in the running app, not in a separate story or sandbox. |
| [Safe](/docs/concepts#blocked-events) | A preview changes only what components see. The real machine keeps running, and events that the UI sends during a preview are blocked and logged. |
| [Realistic data](/docs/concepts#context-for-a-preview) | Previews use context recorded from earlier visits, context you write as fixtures, or the live context. The panel shows which one it uses. |
| [Hidden](/docs/install#before-you-release) | `<Shiru />` renders nothing in a production build, and the registry and the panel are removed from the bundle. |

## Adapters

shiru has an adapter for each kind of machine, and neither is the default. An app can use one of them or both. [Choose an adapter](/docs/concepts#choose-an-adapter) compares them.

### Reducer machines

If a component keeps a union of states in `useReducer`, declare the reducer as a machine with `defineReducerMachine`, and call `useMachineReducer` instead of `useReducer`. The app does not need XState. Refer to [useReducer](/docs/reducer).

### XState machines

The adapter needs two changes to your app. Mount `<Shiru />`, and import the hooks from `shiru/xstate` instead of `@xstate/react`. Refer to [XState](/docs/xstate).
