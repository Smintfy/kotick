shiru turns off only when `process.env.NODE_ENV` is `"production"`. Test runners such as Vitest and Jest set it to `"test"`. Thus, in your tests, shiru works as it does in development.

## What shiru does in a test

What shiru does depends on the test environment:

| Environment | What shiru does |
|---|---|
| A DOM, such as `jsdom` | `useMachineReducer`, the hooks of `shiru/xstate` and `connect()` register each instance in a registry on `globalThis`. shiru records the context of each instance in `sessionStorage`, under keys that start with `shiru:recorded:`. If the test renders `<Shiru />`, shiru adds a `<div data-shiru-root>` to `document.body`. |
| `node`, with no DOM | Nothing. shiru does nothing when `window` or `document` is missing, as on the server. |

Without a preview, `useMachineReducer` behaves as it does in production, and the hooks of `shiru/xstate` behave as the hooks of `@xstate/react`. Thus, your tests do not have to change. shiru writes nothing to the console when it has no problem.

A test that reads `sessionStorage` also sees the keys of shiru. shiru writes them 500 ms after a transition, so a write can occur during the next test.

## Turn shiru off in tests

Mock `shiru` in a setup file, so that `<Shiru />` renders nothing. This example is for Vitest:

```ts
// vitest.setup.ts
import { vi } from 'vitest';

vi.mock('shiru', () => ({ Shiru: () => null }));
```

Add the file to `test.setupFiles` in the Vitest config. Other test runners have a function that does the same thing, for example `jest.mock()` in Jest.

The next step depends on the adapter:

<AdapterTabs>
  <AdapterTab adapter="reducer">
    Do not mock `shiru/reducer`. Its hook runs your transitions and effects, so a mock must keep them. Without a preview, the hook gives the state and the effects of its production version, because it calls that version. It also registers each instance and writes `shiru:recorded:` keys, as the XState hooks do.
  </AdapterTab>

  <AdapterTab adapter="xstate">
    Also mock `shiru/xstate` in the setup file:

    ```ts
    vi.mock('shiru/xstate', async (importOriginal) => ({
      ...(await importOriginal<typeof import('shiru/xstate')>()),
      ...(await vi.importActual<typeof import('@xstate/react')>('@xstate/react')),
      connect: <TActor>(actor: TActor) => actor,
    }));
    ```

    Then, in each test, the hooks are the hooks of `@xstate/react`, and `connect()` returns the actor that you give it. `defineFixtures()` does not change.
  </AdapterTab>
</AdapterTabs>

## Test a reducer machine

`machine.reducer` is the plain reducer of a [reducer machine](/docs/reducer), so a test of its transitions needs no React. For the search machine, `searchMachine.reducer({ status: 'idle' }, { type: 'SEARCH', query: 'linen' })` returns `{ status: 'loading', query: 'linen' }`. A state that does not list an event returns the same object, so `toBe(state)` checks that the state ignores the event.
