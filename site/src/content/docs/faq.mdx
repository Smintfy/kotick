<Faq>
  <FaqItem id="machine-not-in-panel">
    <FaqQuestion>My machine is not in the panel. Why?</FaqQuestion>
    <FaqAnswer>
      Make sure that `<Konat />` is mounted. For a reducer machine, make sure that the component calls `useMachineReducer`. A component that gives `machine.reducer` to `useReducer` is not listed. For an XState machine, make sure that the component imports the hook from `konat/xstate`, not from `@xstate/react`. An actor that you create with `createActor()` must go through `connect()`. To find imports from `@xstate/react`, add a [lint rule](/docs/xstate#prevent-imports-from-xstatereact). With either adapter, an instance with `debug: { disabled: true }` is not listed.
    </FaqAnswer>
  </FaqItem>

  <FaqItem id="preview-side-effects">
    <FaqQuestion>Can a preview change my data or call my API?</FaqQuestion>
    <FaqAnswer>
      No. The real machine does not change, and events that the UI sends during a preview are blocked. Effects in components still run, for example a `useEffect` that fetches when a state shows. They run as they do when the real machine is in that state.
    </FaqAnswer>
  </FaqItem>

  <FaqItem id="preview-wrong-data">
    <FaqQuestion>Why does a preview show the wrong data?</FaqQuestion>
    <FaqAnswer>
      A reducer machine does not use the live context for another state. The panel greys out such a state until it has a recording or a fixture. For an XState machine, the state had no recording and no fixture, so the preview uses the live context. The console shows a warning, and the state tree marks the state. Go to the state once in the real app, or write a [fixture](/docs/fixtures) for it.
    </FaqAnswer>
  </FaqItem>

  <FaqItem id="react-18-strict-mode">
    <FaqQuestion>Does it work with React 18 and StrictMode?</FaqQuestion>
    <FaqAnswer>
      Yes. The test suite runs on React 18 and 19, with StrictMode on.
    </FaqAnswer>
  </FaqItem>

  <FaqItem id="use-reducer">
    <FaqQuestion>Does it work with `useReducer`?</FaqQuestion>
    <FaqAnswer>
      Yes, through `konat/reducer`. Declare the reducer as a machine that names each state, and call `useMachineReducer` instead of `useReducer`. Refer to [useReducer](/docs/reducer).
    </FaqAnswer>
  </FaqItem>

  <FaqItem id="other-state-libraries">
    <FaqQuestion>Does it work with Zustand or other state libraries?</FaqQuestion>
    <FaqAnswer>
      Not in this version. konat lists states that the UI never went to, so it needs a machine that declares its states. Reducer machines and XState machines do. Support for other libraries is on the roadmap.
    </FaqAnswer>
  </FaqItem>

  <FaqItem id="xstate-versions">
    <FaqQuestion>Does it work with XState v4 or v6?</FaqQuestion>
    <FaqAnswer>
      No. It works with XState v5 only. Support for v6 will come when v6 is stable.
    </FaqAnswer>
  </FaqItem>

  <FaqItem id="staging-builds">
    <FaqQuestion>Can I use it in a staging build?</FaqQuestion>
    <FaqAnswer>
      Not in this version. The panel works only in development builds. In a staging build in production mode, `<Konat />` renders nothing.
    </FaqAnswer>
  </FaqItem>

  <FaqItem id="two-copies">
    <FaqQuestion>Two copies of konat are in my bundle. Is that a problem?</FaqQuestion>
    <FaqAnswer>
      No. All copies use one registry on `globalThis`. If the versions are different, the console shows a warning.
    </FaqAnswer>
  </FaqItem>
</Faq>
