  title: 'Fixtures',
  description: 'Give context to the states that you have not recorded yet.',
};

Fixtures give context to states that you have not recorded yet, such as an error after a slow request. Put them in a file of their own, and give `<Konat />` a loader for that file:

```ts
// src/debug/fixtures.ts
import { defineFixtures } from 'konat/xstate';
import { checkoutMachine } from '@/machines/checkout';

const base = { items: [{ id: 'sku_1', name: 'Linen tote', price: 2400, qty: 2 }], total: 4800, cardNumber: '' };

export default [
  defineFixtures(checkoutMachine, {
    'payment.error': { context: { ...base, cardNumber: '4000 0000 0000 0002', error: 'Card declined' } },
    'payment.success': { context: { ...base, receiptId: 'rcpt_123' } },
  }),
];
```

```tsx
// The condition removes the fixtures, and the import, from production builds.
const fixtures = process.env.NODE_ENV !== 'production' ? () => import('@/debug/fixtures') : undefined;

<Konat fixtures={fixtures} />;
```

In Vite, you can use `import.meta.env.DEV` as the condition.

- The keys are leaf ids. TypeScript checks them against the states of the machine, and `context` against the context type of the machine.
- A fixture set applies to each instance of its machine, also to copies from `machine.provide()`, and to machines that `debug.id` renames.
- The loader runs after the page loads. Previews that started before it finished change to the fixture when it arrives. Such a preview logs the warning about the live context only if the loader gives no fixture for it.
- In a parallel preview, the first leaf that has a fixture gives the context: the leaves you selected, in sequence, then the leaves of the other regions.
- You can give an array of sets in place of a loader. Then the sets are in your main bundle, also in production. Use a loader with a development check to keep them out.
