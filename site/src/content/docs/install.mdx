konat has an adapter for each kind of machine. `konat/xstate` is for XState v5 machines, and `konat/reducer` is for `useReducer` machines. Neither is the default. Select the adapter that your app uses:

<AdapterTabs>
  <AdapterTab adapter="xstate">
    <InstallTabs packages="konat xstate @xstate/react" />

    The command also installs `xstate` and `@xstate/react`, because konat does not install them. If your app already has them, install only `konat`. An app can use both adapters, and this command installs all that both need.
  </AdapterTab>

  <AdapterTab adapter="reducer">
    <InstallTabs packages="konat" />

    `konat/reducer` needs only React. Your app does not need `xstate` or `@xstate/react`.
  </AdapterTab>
</AdapterTabs>

Add konat to `dependencies`, not to `devDependencies`. Your app code imports `konat/xstate` or `konat/reducer`, thus the production build needs the package.

## Requirements

konat uses the versions of these packages that your app has:

| Package | Versions | Needed for |
|---|---|---|
| `react`, `react-dom` | 18 or 19 | Both adapters |
| `xstate` | 5.28 or later | `konat/xstate` only |
| `@xstate/react` | 6.1 or later | `konat/xstate` only |

## Quick start

1. Mount the overlay once, near the root of the app. Both adapters use the same overlay:

   ```tsx
   import { Konat } from 'konat';

   export function App() {
     return (
       <>
         <Routes />
         <Konat />
       </>
     );
   }
   ```

2. Connect your machines through the adapter:

   <AdapterTabs>
     <AdapterTab adapter="xstate">
       Import the XState hooks from `konat/xstate` instead of `@xstate/react`:

       ```diff
       - import { useMachine, useSelector, createActorContext } from '@xstate/react';
       + import { useMachine, useSelector, createActorContext } from 'konat/xstate';
       ```

       The hooks have the same names and signatures as in `@xstate/react`.
     </AdapterTab>

     <AdapterTab adapter="reducer">
       Declare the reducer as a machine with `defineReducerMachine`. Then call `useMachineReducer` instead of `useReducer`:

       ```diff
       - const [state, dispatch] = useReducer(reducer, { status: 'idle' });
       + const [state, dispatch] = useMachineReducer(searchMachine, { status: 'idle' });
       ```

       [From a switch reducer](/docs/reducer#from-a-switch-reducer) shows how to change a reducer into a machine.
     </AdapterTab>
   </AdapterTabs>

Start the dev server and click the bubble in the bottom-right corner, or press <Shortcut mac="⌥S" other={['Alt', 'S']} />. The panel lists each machine that runs on the page. Select a machine to see its states. Select a state to preview it, and select it again to release it.

## Actors outside React

With `konat/xstate`, actors that you create outside React, for example in a module, need one more step. Wrap them with `connect()`:

```ts
import { createActor } from 'xstate';
import { connect } from 'konat/xstate';
import { sessionMachine } from '@/machines/session';

export const sessionActor = connect(createActor(sessionMachine).start(), { id: 'session' });
```

Use the actor that `connect()` returns everywhere in the app, for example with `useSelector(sessionActor, …)`.

## Prevent imports from @xstate/react

A component that imports a hook from `@xstate/react` continues to work, but the panel does not list its machine. To find these imports, add the `no-restricted-imports` rule to your linter. `konat/xstate` exports all the functions of `@xstate/react`, so the rule can block the full package. For ESLint:

```js
// eslint.config.js
export default [
  {
    rules: {
      'no-restricted-imports': [
        'error',
        {
          name: '@xstate/react',
          message: 'Import the XState hooks from konat/xstate, so that the panel lists the machine.',
        },
      ],
    },
  },
];
```

Oxlint has the same rule, with the same options.

## Check the install

You can check the install without a screen, for example in a browser test or from an agent. In development, `<Konat />` adds a `<div data-konat-root>` to `document.body`, or to `portalTarget`. The overlay is in the open shadow root of this element.

1. Get the shadow root:

   ```js
   const shadow = document.querySelector('[data-konat-root]')?.shadowRoot;
   ```

   If `shadow` is `undefined`, `<Konat />` is not mounted, or the page is from a production build.

2. Open the panel:

   ```js
   shadow.querySelector('button[aria-label^="Konat"]').click();
   ```

3. After the panel renders, read the machine ids:

   ```js
   [...shadow.querySelectorAll('[data-machine]')].map((row) => row.getAttribute('data-machine'));
   ```

   The result is a list such as `['checkout']`. If a machine is not in the list, refer to the [FAQ](/docs/faq).

The panel keeps its open state and its page from the last visit. Thus, in a browser that used the panel before, step 2 can close the panel, or open the page of one machine. To start with a closed panel, [reset the panel](/docs/troubleshooting#reset-the-panel) before step 1.

konat writes nothing to the console when it starts. A message that starts with `[konat]` tells you about a problem. Refer to [Troubleshooting](/docs/troubleshooting#console-warnings).
