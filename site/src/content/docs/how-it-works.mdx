kotick has three parts: an adapter for each kind of machine, one registry for the page, and the overlay. The adapters register your machines in the registry. The overlay reads the registry, and writes the preview that you select to it.

## One registry holds every instance

Each component that calls `useMachineReducer`, and each proxy of an XState actor, registers under a machine id and an instance id. The machine id is `machine.id`. For an XState machine, `debug.id` replaces it if you set it.

The registry is on `globalThis`, so all React roots and all copies of kotick on the page share it. On the server, the registry does nothing, because one server process renders the pages of many users.

## The states come from the machine definition

kotick reads the states from the machine once and keeps the tree. So the panel can list the states that the app never visited. Each state of a reducer machine is a leaf. In an XState machine, each atomic or final state is a leaf. You can preview each leaf.

## The reducer adapter keeps the state in React

`useMachineReducer` runs the reducer of the machine in React's `useReducer`, and runs the effect of the real state. In development, it also registers the instance, records its state object after each commit, and returns the state object of a preview in place of the real one.

A preview changes only the state object that the hook returns. The real state stays in `useReducer`, and its effect continues to run. During a preview, `dispatch` logs each event in the panel and does not pass it to the machine. The `send` of a machine effect always goes to the real machine.

## The XState adapter gives components a proxy

The hooks of `kotick/xstate` call the hooks of `@xstate/react`, and return a proxy of the actor that they make. `connect()` does the same for an actor that you create outside React. The proxy passes each call to the real actor. During a preview, `getSnapshot()`, `subscribe()`, and `send()` work differently.

When you select a leaf, the registry keeps an override for that instance, with the leaves and a context. The proxy gives them to `machine.resolveState()`, and returns the snapshot that XState makes from `getSnapshot()` and to subscribers. The components render again with a real XState snapshot, so `matches()`, `hasTag()`, and `can()` work. In a parallel machine, the regions that you did not select keep their current leaf. The live child actors are copied into the preview. The real actor does not know about the preview, and continues to run.

During a preview, `send()` on the proxy checks for an override first. So does the internal send that `sendTo()`, `forwardTo()`, and delayed events use. If there is an override, the event goes to the event log of the panel, not to the actor.

## Recordings stay in memory and in sessionStorage

kotick records the context of each instance in memory, under its set of leaves. Every 500 ms, it writes a JSON copy of the recordings to `sessionStorage`, within the limits in [Recordings](/docs/limitations#recordings). The copy has no functions. A context that JSON cannot copy correctly, such as one with an actor ref, stays only in memory.

A preview uses the recording of the same set of leaves. If there is none, it uses the newest recording that has a selected leaf. If there is no recording, it uses a [fixture](/docs/fixtures), and then the live context, as [Context for a preview](/docs/concepts#context-for-a-preview) describes.

## The overlay renders in a shadow root

`<Kotick />` adds a `<div data-kotick-root>` to `document.body`, or to `portalTarget`. It attaches a shadow root to the `div`, puts the CSS of the overlay in it, and renders the panel there with a React portal. So the styles of the page and the styles of the overlay cannot affect each other. kotick adds the `div` in a layout effect, after hydration, so the server renders nothing.

## Production builds drop the overlay and the registry

`<Kotick />`, the hooks of each adapter, `createActorContext()`, and `connect()` each pick a version with `process.env.NODE_ENV !== 'production' ? <development version> : <production version>`. The bundler replaces `process.env.NODE_ENV` with `"production"` and removes the branch that cannot run. The package sets `"sideEffects": false`, so the bundler also removes the modules that nothing imports. `<Kotick />` becomes a component that returns `null`. [Choose an adapter](/docs/concepts#choose-an-adapter) shows what each adapter keeps, and its size.
