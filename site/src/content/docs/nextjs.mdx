`konat` and `konat/xstate` start with `'use client'`, so you can import them in the App Router.

`konat/reducer` has no directive, so any module can import a machine file, also a server component or a route handler. Only client components call `useMachineReducer`.

## Server components

- A server component can render `<Konat />`.
- A server component cannot give a function to a client component, so it cannot give the `fixtures` loader. Render `<Konat fixtures={…} />` in a client component:

  ```tsx
  // src/components/dev-tools.tsx
  'use client';

  import { Konat } from 'konat';

  const fixtures = process.env.NODE_ENV !== 'production' ? () => import('@/debug/fixtures') : undefined;

  export function DevTools() {
    return <Konat fixtures={fixtures} />;
  }
  ```

- Call the hooks of `konat/xstate` and `createActorContext()` only in client components, as with `@xstate/react`.
- Call `useMachineReducer` only in client components. A server component can import a machine file of `konat/reducer`, call `machine.reducer`, and give the state that it returns to a client component as a prop.
- On the server, konat does nothing: the overlay renders nothing, and nothing registers. The overlay mounts after hydration, so it does not cause hydration errors.

## Root layout

Render the overlay in the root layout, after `{children}`. The root layout stays mounted when the page changes. Thus, the panel stays open while the machines of each page register and unregister.

```tsx
// src/app/layout.tsx
import type { ReactNode } from 'react';
import { DevTools } from '@/components/dev-tools';

export default function RootLayout({ children }: { children: ReactNode }) {
  return (
    <html lang="en">
      <body>
        {children}
        <DevTools />
      </body>
    </html>
  );
}
```

## Pages Router

konat also works in the Pages Router. Render `<Konat />` in `pages/_app.tsx`, so that it stays mounted when the page changes:

```tsx
// src/pages/_app.tsx
import type { AppProps } from 'next/app';
import { Konat } from 'konat';

const fixtures = process.env.NODE_ENV !== 'production' ? () => import('@/debug/fixtures') : undefined;

export default function App({ Component, pageProps }: AppProps) {
  return (
    <>
      <Component {...pageProps} />
      <Konat fixtures={fixtures} />
    </>
  );
}
```

The Pages Router has no server components. Thus, `_app.tsx` can give the `fixtures` loader, and each page and component can call the hooks of both adapters. During server rendering, konat does nothing, as in the App Router.
