## Props

`<Konat />` from `konat` takes these props. All props are optional.

<PropsTable>
  <Prop name="position" type="Position" detailedType="'top-left' | 'top-right' | 'bottom-left' | 'bottom-right'" default="'bottom-right'">
    The corner of the bubble and the panel.
  </Prop>
  <Prop name="defaultOpen" type="boolean" default="false">
    Opens the panel on the first visit.
  </Prop>
  <Prop name="shortcut" type="string | false" default="'alt+s'">
    The keys that open and close the panel. `false` turns the shortcut off. Refer to [Shortcut](#shortcut).
  </Prop>
  <Prop name="fixtures" type="FixturesInput" detailedType="readonly FixtureSet[] | (() => FixturesResult | PromiseLike<FixturesResult>)">
    Fixture sets, or a function that loads them. Refer to [Fixtures](/docs/fixtures).
  </Prop>
  <Prop name="portalTarget" type="Element | ShadowRoot" default="document.body">
    The element that gets the host element of the overlay.
  </Prop>
</PropsTable>

The panel keeps its open state, its corner and the machine whose page it shows in `localStorage`, so `position` and `defaultOpen` apply only until the user changes them. The user changes the corner in **Settings**. After a reload, the panel shows the page of the same machine when that machine registers.

The overlay renders in a shadow root, so the styles of the page do not change it, and its styles do not change the page. It is dark on every page.

In production builds, `<Konat />` renders nothing and does not call the fixtures loader.

### Shortcut

Write the parts of a shortcut with `+` between them, for example `ctrl+shift+d`. The last part is the key, and the other parts are modifiers. Uppercase letters and spaces have no effect.

| Modifier | Other names |
|---|---|
| `alt` | `option`, `opt` |
| `ctrl` | `control` |
| `shift` | |
| `meta` | `cmd`, `command` |
| `mod` | ⌘ on macOS, Ctrl on other systems |

The key is a value of `KeyboardEvent.key`, for example `s`, `f2` or `escape`. These names are also accepted: `esc`, `space`, `up`, `down`, `left`, `right`, `return`, `del`, and `plus` for the `+` key.

- The modifiers must agree exactly. `alt+s` does not open the panel when the user also holds Shift.
- For letters and digits, the physical key also agrees. Thus, `alt+s` works on macOS, where Alt+S types `ß`, and on keyboard layouts that move the letters.
- The shortcut does nothing while the focus is in a text field.
- konat ignores a shortcut that it cannot read, and logs a warning: `[konat] Ignoring the shortcut "…": expected something like "alt+s".`

## Exports

`konat/xstate` has these exports:

| Export | What it is |
|---|---|
| `useMachine(machine, options?)` | Same as `@xstate/react`. Returns `[snapshot, send, actorRef]`. |
| `useActor(logic, options?)` | Same as `@xstate/react`. Returns `[snapshot, send, actorRef]`. |
| `useActorRef(logic, options?, observer?)` | Same as `@xstate/react`. Returns the actor. |
| `createActorContext(logic, options?)` | Same as `@xstate/react`. Its `Provider` creates the actor. |
| `useSelector(actor, selector, compare?)` | Same as `@xstate/react`. It works with each actor from this package. |
| `shallowEqual` | A re-export of `@xstate/react`. |
| `connect(actor, debug?)` | Registers an actor that you created outside React. Returns the actor to use in the app. |
| `defineFixtures(machine, states)` | Makes a fixture set for `<Konat fixtures>`. |

The actors that the hooks return are proxies of the real actors. They have the same interface. `actorRef.send()` goes to the real actor when nothing is previewed.

### The debug option

The hooks and `createActorContext` accept one more option, `debug`. `connect()` takes the same object as its second argument.

```ts
type DebugOptions = {
  id?: string;        // The machine id in the panel. The default is machine.id.
  label?: string;     // The name of the instance in the panel.
  disabled?: boolean; // Keep this actor out of konat.
};

const [snapshot, send] = useMachine(checkoutMachine, { input, debug: { label: 'Checkout (modal)' } });
```

In development, konat removes `debug` before the options get to XState. In production builds, the hooks are the hooks of `@xstate/react`, so XState also gets `debug`. XState keeps it in `actor.options` and does nothing with it.

Give each machine an `id`. A machine without one has the XState default id `(machine)`. konat then makes an id from the states and context keys of the machine, and logs a warning once. That id changes when you add or remove states or context keys, so the previews and recordings of the machine do not carry over after such a change.

### connect()

`connect()` registers the actor immediately, and unregisters it when the actor is done, fails or stops. Use the actor that `connect()` returns everywhere in the app. Refer to [Actors outside React](/docs/install#actors-outside-react).

`connect()` returns the actor unchanged, and does not register it, when:

- The actor is not a machine actor, for example a promise actor.
- The actor is done, failed or stopped.
- `debug.disabled` is `true`.
- The build is a production build.

An actor that konat registered before does not register again. This includes an actor from `connect()`, an actor from a hook, and the real actor of either. `connect()` returns the proxy that the actor already has, with its first id and label. If the actor is from a hook and you give `id` or `label`, konat logs a warning.

## Types

`konat` exports these types:

| Type | What it is |
|---|---|
| `KonatProps` | The props of `<Konat />`. |
| `Position` | `'top-left' \| 'top-right' \| 'bottom-left' \| 'bottom-right'` |
| `FixtureSet` | The return value of `defineFixtures()`: `{ machineId: string; states: Record<string, { context: unknown }> }`. |
| `FixturesResult` | `readonly FixtureSet[]`, or a module whose default export is `readonly FixtureSet[]`, as `import()` gives it. |
| `FixturesInput` | `readonly FixtureSet[]`, or a function that returns a `FixturesResult` or a promise of one. |

`konat/xstate` exports these types:

| Type | What it is |
|---|---|
| `DebugOptions` | The `debug` option of the hooks and the second argument of `connect()`. |
| `FixtureStates<TMachine>` | The second argument of `defineFixtures()`: an optional `{ context }` for each leaf id. `context` has the context type of the machine. |
| `LeafIdFrom<TMachine>` | The leaf ids of a machine as a union, for example `'cart' \| 'payment.error'`. It is `string` when TypeScript cannot know the states. |
